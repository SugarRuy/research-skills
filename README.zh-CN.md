# Research Skills

[English](README.md) | [简体中文](README.zh-CN.md)

面向科研与科学写作的实用 skill 集合。每个模块处理一个明确任务，可以独立使用，也可以接入更大的科研流程。Skill 指令使用英文；输出可以按你的要求使用中文或其他语言。

现有模块帮助研究者判断投稿就绪程度，并修订已有稿件的信息组织与表达。

## 现有模块

| Skill | 适用场景 | 输出 |
| --- | --- | --- |
| [Paper Submission Acceptance](skills/paper-submission-acceptance/SKILL.md) | 已有稿件，需要判断投稿就绪程度、明确修改重点，或复查已完成的修改。 | 有依据的就绪判断、实质阻塞项、收尾工作、未核验事项，以及具体完成条件。 |
| [Paper Editorial Refinement](skills/paper-editorial-refinement/SKILL.md) | 段落、表注、公式或相互关联的稿件内容不易理解，需要检查、修改方案或实际修订。 | 根据信息作用作出具体编辑选择，在授权范围内协调关联修改，并检查科学含义与引用关系是否保持。 |

## 论文投稿就绪评估

论文修改了很多轮，仍然不知道能否投稿。新一轮检查又增加了建议，却没有说明哪些必须完成、什么时候可以停止修改。

这个 skill 从研究问题、贡献、论证、证据、可读性和最终材料出发，判断哪些问题需要实质修改、哪些可以进入收尾，以及哪些部分已经达到要求。

评估重点包括：

- **正文证据可核查。** 正文中有实质论证作用的数字应展示在主图表中，或能从展示值透明推导。如果一项次要数字结果移到附录，依赖它的详细解释也应一起移动。设计数量、数学常数和示例阈值不自动视为结果估计。
- **问题有完成条件。** 每项影响判断的发现包含位置、证据、对就绪程度的影响，以及解决条件。材料缺失应标为未核验，不凭空判为失败。
- **修改能够收敛。** 多轮检查保留已经解决的决定；只有新证据、相关稿件修改或实际矛盾才重新打开问题。局部措辞偏好不应让实质修改重新开始。

报告首先给出一种状态：

| 状态 | 含义 |
| --- | --- |
| 需要实质修改 | 已发现的问题使核心主张无法被评估或支持。 |
| 可以进入收尾 | 研究和论证已经稳定，剩下范围明确的呈现或材料工作。 |
| 可以投稿 | 当前检查版本通过实质标准和适用的最终检查。 |
| 尚未充分核验 | 材料或检查缺失，暂时无法给出完整判断。 |

评估本身不会提交或修改稿件，也不预测录用结果。如果你同时要求修复问题，skill 支持完成已授权的修改。

## 本地使用与验收示例

从 `skills/` 中选择所需模块，将其完整文件夹复制到所用 agent 支持的 skill 目录，或让 agent 读取该模块的 `SKILL.md`。保留模块附带的参考材料。两个模块均不依赖其他 skill 或脚本。文件读取、PDF 查看和搜索工具的可用性决定哪些检查能完成；无法执行的检查必须标为未核验。

提供当前稿件、相关图表和附录。最终核验还需要实际渲染的 PDF 和适用的投稿要求。复查时可附上上一轮发现。材料不完整时也可以开始，但判断会注明覆盖范围。

调用示例：

- “使用 paper-submission-acceptance 评估这篇稿件，区分实质问题与收尾工作。”
- “检查正文讨论的实质数字是否有正文图表支持。”
- “结合本次修改复查上一轮问题；不受修改影响的已解决事项保持关闭。”
- “现在能否停止实质修改？说明还有什么影响就绪判断。”

两个虚构示例展示具体评估方式：

- [可以从主表透明推导的结果](examples/submission-readiness.md)：区分措辞收尾与尚未核验的最终检查。
- [数字证据只在附录中](examples/missing-main-text-evidence.md)：识别未满足的展示要求，并在不凭空要求新实验的前提下解决问题。

示例用于说明行为，不代表实测效果。

## 论文信息组织与表达修订

科学内容正确，读者仍可能难以理解：公式的计算对象定义得太远，表注把必要读法与完整流程混在一起，或同一个方法在定义和结果中使用了不同名称。

这个模块把具体障碍转化为编辑选择：

**识别阅读障碍 → 判断信息作用 → 选择编辑动作 → 落实关联修改 → 检查障碍是否解决。**

可选动作包括补充有依据的解释、改写含糊关系、移动信息、合并重复内容，以及保持原文。理解和判断结果所需的信息应保持可访问；完整复现细节可以放附录，前提是不削弱正文论证。表注保留当前图表所需的阈值、符号和分母说明。修订保持事实、数字、公式语义、结论强度及真实限制。

提供片段或稿件、相关定义和图表，并说明需要检查、拟议措辞还是实际修改。版面问题应附实际渲染页面；有审美偏好时明确说明。局部任务可以只提供片段，无法检查的关联内容会标为覆盖限制。

调用示例：

- “使用 paper-editorial-refinement 检查这段表注：哪些信息应留在这里，哪些放方法或附录？不要改文件。”
- “根据提供的定义，提出这个公式的解释，保持分母和比较方向。”
- “修订方法介绍、表格标签和结果引用，让它们对应同一个操作，并同步表注生成器。”
- “删除重复的防御性表达，保留不确定性、负面结果和解释结论所需的限制。”
- “检查这一段是否确实需要修改；保持原文也可以。”

[五个虚构编辑案例](skills/paper-editorial-refinement/references/editorial-cases.md) 展示输入、障碍、选择、拟议结果和适用边界，也包括有理由保持原文的情况。它们说明决策方式，不代表实测效果。

## 在科研流程中的位置

需要判断稿件是否就绪、还需完成什么时，调用 **Paper Submission Acceptance**。需要决定具体信息如何解释和安排时，调用 **Paper Editorial Refinement**，未完成的局部稿件也适用。前者同样可以协助修复问题；后者新增的是根据信息作用选择动作、协调关联修改的方法。两个模块不会自动启动彼此。

共同约束是保持科学含义、证据可访问性、授权范围和如实核验。完整就绪标准与状态判断由验收模块维护，编辑动作选择与案例由修订模块维护。仅为独立使用保留少量重叠的保护约束；修改重叠约束时检查两边一致性，不复制整套工作流，也不增加强制共享依赖。

后续任务明确后，再向 `skills/` 添加模块。每个模块应说明适用场景、输出，以及完成条件。
